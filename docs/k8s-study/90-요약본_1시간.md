# K8s 오브젝트 28종 — 1시간 요약본 (당당 이관 기준)

> `docs/k8s-study` 01~28 전체 압축. 오브젝트당 3줄 = **정의 / 절대 틀리면 안 되는 핵심 / 당당 적용**. 상세·공식 링크는 각 원문과 맨 아래 §5 참조.

## 1. 개요 지도 — 누가 무엇을 지키나/재나

```
■ 어드미션 관문 (파드가 뜨기까지 — 요청이 지나는 순서)
  인증 SA(04) → 인가 RBAC: Role(05)·ClusterRole(06) ⟵배선⟵ RoleBinding·CRB(07)
  → Mutating(Kyverno mutate·Vault Injector) → Validating(PSA(01)·Kyverno(12) validate)
    ※ 두 단계의 동작 원리 = Admission Webhook(13), Mutating이 항상 먼저
  → ResourceQuota(26)·LimitRange(27) 자원 검사 → etcd 저장(암호화 10)
  … 이 전 과정을 "누가·언제·무엇을"로 기록 = Audit Policy(14)

■ 뜬 파드를 지키는 것
  Namespace(23)=정책 경계 + NetworkPolicy(03)=L3/L4 화이트리스트 + SecurityContext(02)=최소 권한 실행값
  시크릿: SealedSecret(09, Git 봉인) → Secret(08, 종착지) → etcd 암호화(10, 자물쇠) / TLS = Certificate·Issuer(11)

■ 파드를 돌리는 것
  Deployment(25, 무상태·롤링) / StatefulSet(15, 고유 신원+전용 PVC) / DaemonSet(16, 노드당 1)
  + Probes(19, 재시작·트래픽·시작보호) + HPA(20, 개수 자동) + PDB(28, 동시다운 제한) + Service(24, 고정 VIP·DNS)

■ 재는 것 · 담는 것
  ServiceMonitor·PodMonitor(17, 무엇을 긁나) → PrometheusRule(18, 언제 울리나) → Alertmanager(발송)
  StorageClass(22, 공장) ─동적 생성→ PV(21, 실물) ⟵1:1 바인딩─ PVC(21, 요청서) ⟵참조─ 파드
```

## 2. Tier별 3줄 요약

### 🔴 Tier 1 · 보안 (01~14)

- **01 PSA** — 파드 생성 시 보안 설정을 **네임스페이스 라벨**로 검사하는 내장 어드미션 컨트롤러(3레벨 privileged/baseline/restricted × 3모드 enforce/audit/warn, v1.25 GA·PSP 후계).
  - ⚠ `enforce`는 **최종 파드에만** 적용 — 위반 Deployment는 apply 성공 후 **replica 0 조용한 실패**(warn/audit 병행 필수).
  - 당당: 원칙 `enforce=restricted`, `dang-db-ns`만 baseline(root DB 이미지) — ※공식 PSS상 hostPath·hostNetwork는 **baseline도 금지**라 관측 DaemonSet은 privileged 필요(92 통합본 정정 공지 참조), `-version` 라벨로 버전 고정.
- **02 SecurityContext** — 파드/컨테이너가 어떤 UID·권한·커널 능력으로 실행될지 지정하는 매니페스트 필드(PSA가 gate라면 이것은 통과할 값).
  - ⚠ 파드/컨테이너 레벨이 겹치면 **컨테이너 우선**, `readOnlyRootFilesystem`은 restricted **필수 아님**(권장).
  - 당당: 하드닝 4종(runAsNonRoot + allowPrivilegeEscalation:false + drop ALL + seccomp RuntimeDefault) = restricted 통과 최소 조합.
- **03 NetworkPolicy** — 파드 간 통신을 L3/L4에서 화이트리스트로 제어하는 선언적 방화벽(정책이 선택하는 순간 격리).
  - ⚠ 기본은 **전부 허용** + 정책 지원 CNI(Calico/Cilium) 없으면 **조용히 무시**됨.
  - 당당: 전 ns default-deny(Ingress+Egress) 후 fe→be→db만 개방, DNS(53)·Prometheus scrape 예외 필수.
- **04 SA(ServiceAccount)** — 파드가 API 서버에 신원을 증명하는 기계용 신분증(K8s에 사람용 User 오브젝트는 없음).
  - ⚠ SA는 **인증만** — 바인딩 전 권한 0, 그러나 default SA 토큰 자동 마운트 자체가 리스크.
  - 당당: 워크로드별 전용 SA, 앱·DB ns는 `automountServiceAccountToken: false`, default SA 권한 부여 금지.
- **05 Role** — 하나의 네임스페이스 안 리소스 권한 묶음(apiGroups+resources+verbs, `""`=코어 그룹).
  - ⚠ RBAC은 **허용만 있고 deny 없음**(additive) — 처음부터 좁게 주는 게 유일한 방어.
  - 당당: 네임스페이스 안에서 끝나는 권한은 전부 Role+RoleBinding, 전역 금지 원칙.
- **06 ClusterRole** — 네임스페이스 경계 없는 권한 묶음: non-namespaced 리소스(Node·PV)+`nonResourceURLs`(/metrics)까지.
  - ⚠ RoleBinding으로 묶으면 **그 ns로만 축소** — "ClusterRole=무조건 전역" 아님(최다 오답 지점).
  - 당당: Prometheus·kube-state-metrics 등 전 ns 디스커버리+Node 접근이 필요한 소수만, 읽기 전용으로 좁게.
- **07 RoleBinding & CRB** — Role/ClusterRole을 주체(SA·User·Group)에 연결하는 배선(권한 내용은 안 담음, `roleRef` 불변).
  - ⚠ CRB는 **ClusterRole만** 참조 가능 — Role+CRB는 4조합 중 유일한 불가(스코프 모순).
  - 당당: Prometheus SA = read ClusterRole+CRB, 단일 ns는 Role+RB, 공용 패턴은 ClusterRole+ns별 RB 재사용.
- **08 Secret** — 민감 소량 데이터를 파드와 분리해 저장·주입하는 오브젝트(env 또는 tmpfs 볼륨으로 소비, 1MiB 제한).
  - ⚠ **base64는 인코딩일 뿐 암호화 아님** — 기본은 etcd 평문 저장, 보호는 RBAC+etcd 암호화 조합.
  - 당당: 모든 시크릿 계층의 종착지 — `dockerconfigjson`(Harbor pull)·`tls`(cert-manager)·`Opaque`(DB 계정).
- **09 SealedSecret** — Secret을 클러스터 공개키로 봉인해 Git 커밋 가능하게 만드는 CRD(컨트롤러의 개인키만 복호화).
  - ⚠ **sealing key 유실 = Git의 모든 SealedSecret 영구 복호화 불가** — 축적된 키 전체 백업이 생명줄.
  - 당당: GitOps 부트스트랩 계층(DB 초기 비번·Harbor 자격증명), 스코프 `strict` 유지, `dang-sealed-secrets-ns`.
- **10 etcd Encryption at Rest** — apiserver가 Secret을 etcd에 쓰기 전 암호화하는 `EncryptionConfiguration`(기본은 평문 저장).
  - ⚠ **첫 프로바이더만 새 쓰기를 암호화** + 기존 Secret은 재기록해야 적용(소급 안 됨).
  - 당당: 시크릿 3계층 최후 방어선 — KMS 부재로 aescbc 로컬, master×3 설정 동일 필수, `etcdctl`+hexdump 실측 검증.
- **11 Certificate·Issuer(cert-manager)** — TLS 자동 발급·갱신 CRD: Issuer(ns)/ClusterIssuer(전역)=발급기관, Certificate=요청서 → `kubernetes.io/tls` Secret.
  - ⚠ Certificate는 **같은 ns의 Issuer만** 참조 가능 — 여러 ns 공유 정책이면 ClusterIssuer.
  - 당당: ClusterIssuer 통일(외부 ACME·내부 CA), 9402 메트릭으로 만료 30/7일 전 알람 — 가치는 발급이 아니라 **자동 갱신+알람**.
- **12 Kyverno Policy·ClusterPolicy** — 규칙을 YAML로 선언하면 어드미션 단계에서 validate/mutate/generate 하는 정책 CRD.
  - ⚠ PSA가 못 하는 세밀 정책(레지스트리 강제·latest 금지) 담당 — `Audit` 관측 후 `Enforce` 승격이 정석.
  - 당당: PSA를 완화한 ns(db=baseline, 관측 DaemonSet=privileged)를 validate로 다시 조이고, 신규 ns에 default-deny NetworkPolicy 자동 generate.
- **13 Admission Webhook** — API 서버가 etcd 저장 직전 외부 서비스를 호출해 검증(Validating)/수정(Mutating)하는 확장 지점.
  - ⚠ **Mutating→Validating 순서** + `failurePolicy: Fail`이면 웹훅 장애 시 배포 마비 가능(kube-system 제외 필수).
  - 당당: Kyverno·cert-manager·Vault Agent Injector 3축의 공통 원리 — 장애 시 `apiserver_admission_webhook_*` 지표부터.
- **14 Audit Policy** — apiserver 요청을 "누가·언제·무엇을" 4레벨(None/Metadata/Request/RequestResponse)로 기록하는 감사 설정.
  - ⚠ **기본 비활성** + 규칙은 첫 매칭 승리(순서가 곧 정책), Secret은 `Metadata`로만(값 유출 방지).
  - 당당: 다층 방어의 사후 증명 — OTel Agent가 tail→Loki→LogQL, 민감 리소스만 차등 상세 기록.

### 🔵 Tier 2 · 모니터링 (15~22)

- **15 StatefulSet** — 파드마다 불변 고유 이름(`이름-ordinal`)+전용 영속 볼륨(`volumeClaimTemplates`)을 보장하는 상태 저장 컨트롤러.
  - ⚠ 공식 4조건(안정 신원·안정 스토리지·순서 배포·순서 업데이트) 중 하나라도 필요하면 StatefulSet — 삭제해도 **PVC는 남는다**.
  - 당당: Prometheus(WAL 전용 PVC)·Alertmanager 3(gossip 피어 DNS)·Vault(Raft) — Headless Service 직접 생성 필수.
- **16 DaemonSet** — 모든(또는 선택된) 노드마다 파드를 정확히 1개씩 보장하는 컨트롤러(노드 수 = 파드 수, 자동 추종).
  - ⚠ Deployment replica=노드수와 다름 — 몰릴 수 있고 노드 증가를 자동 추종 안 함; 1.12+부터는 기본 스케줄러가 배치.
  - 당당: node-exporter(8노드 8개)·OTel Collector Agent — hostPath·hostNetwork는 PSS baseline도 금지라 privileged 범위 최소화(DaemonSet ns 분리)로 재조정(92 정정 공지).
- **17 ServiceMonitor·PodMonitor** — "이 라벨의 Service/파드를 이 경로·주기로 긁어라"를 선언하는 Prometheus Operator CRD(재시작 없이 반영).
  - ⚠ 긁는 주체는 CRD가 아니라 **Prometheus**(셀렉터로 선택) — 안 긁히면 90%는 라벨 3단 매칭 또는 named port 문제.
  - 당당: 각 대상 ns에 CRD 배포 + NamespaceSelector로 크로스 발견, GitOps 관리("관측 대상 = 코드").
- **18 PrometheusRule** — 알림 규칙+기록 규칙(recording)을 선언하는 CRD — "언제 울릴지"의 코드화.
  - ⚠ **평가·발화는 Prometheus, 발송·라우팅은 Alertmanager** — Alertmanager는 규칙을 평가하지 않는다.
  - 당당: 알람을 Git(ArgoCD)으로 — up==0·메모리 90%·TLS 만료·Vault sealed 등, Grafana Alerting과 소유권 구분 과제.
- **19 Probes** — kubelet이 컨테이너를 주기 점검해 재시작(liveness)/트래픽(readiness)/시작 보호(startup)를 판단하는 진단 장치.
  - ⚠ liveness 실패=**재시작**, readiness 실패=**트래픽 차단만**(재시작 X); startup 성공 전까지 나머지 프로브 정지.
  - 당당: 앱 3계층 전부 3프로브, `dang-ai-ns` 모델 로딩은 startup으로 보호, liveness는 자기 생존만(외부 의존성 금지).
- **20 HPA + Metrics API** — 지표(기본: CPU 사용률 = 사용량÷requests) 기반으로 replica 수를 자동 조절하는 컨트롤러.
  - ⚠ **metrics-server 필수**(Prometheus로 대체 불가) + requests 미지정이면 CPU% HPA 성립 불가.
  - 당당: 무상태 앱 3계층만 적용, 임계값은 부하테스트 이월로 실측 후 확정 — DaemonSet·고정 replica엔 금지.
- **21 PV & PVC** — PV=클러스터의 실제 스토리지 자원(클러스터 스코프), PVC=사용 요청서(ns 스코프), 파드는 **PVC만 마운트**(배타적 1:1 바인딩).
  - ⚠ RWO는 파드가 아니라 **노드 단위** — 같은 노드의 여러 파드는 동시 접근 가능(단일 파드 강제는 RWOP).
  - 당당: 로컬 PVC(WAL)+MinIO(장기) 2단, 유실 불가 데이터는 `Retain`, Prometheus는 volumeClaimTemplates로 1:1.
- **22 StorageClass** — PVC 요청에 맞춰 provisioner(CSI)가 PV를 동적 생성하게 하는 스토리지 템플릿(주문서).
  - ⚠ 동적 생성 PV의 reclaimPolicy 기본은 **Delete**(정적 PV는 Retain) — 안 지워져야 할 데이터는 Retain 명시.
  - 당당: Longhorn CSI(`driver.longhorn.io`) + `WaitForFirstConsumer`, WAL은 Delete·Vault Raft는 Retain 클래스 분리.

### ⚪ Tier 3 · 공통 (23~28)

- **23 Namespace** — 클러스터를 논리 구획해 이름 스코프와 정책(RBAC·Quota·PSA·NetworkPolicy)의 경계를 제공하는 오브젝트.
  - ⚠ **소프트 격리** — 그 자체로는 네트워크·자원을 차단하지 않음(공식: "네임스페이스 간 보안 강제 안 함"), 정책을 얹어야 격리.
  - 당당: `dang-*` 용도별 구획(앱 4 + obsv + 보안 4) — 폴더가 아니라 정책 경계·폭발 반경 1차 방어선.
- **24 Service** — 바뀌는 파드 집합 앞에 고정 VIP·DNS를 세우는 추상화(ClusterIP/NodePort/LoadBalancer/Headless).
  - ⚠ 상위 타입은 하위를 포함(LB⊃NodePort⊃ClusterIP); Headless(`clusterIP: None`)는 VIP·LB 없이 DNS가 파드 IP 명단 반환.
  - 당당: 프론트만 외부 노출(NodePort/LB, MetalLB 전제), 나머지 ClusterIP, StatefulSet 계열은 Headless.
- **25 Deployment** — 무상태 파드를 replica만큼 유지하며 롤링 업데이트·롤백을 제공하는 컨트롤러(Deployment→ReplicaSet→Pod).
  - ⚠ PVC를 **만들지 않고 참조만** — 여러 replica가 한 PVC 공유라 RWX 아니면 사실상 replica=1.
  - 당당: 앱 3계층 + Grafana(provisioning+SQLite 무상태화)·OTel Gateway·kube-state-metrics·각종 컨트롤러.
- **26 ResourceQuota** — 네임스페이스 **전체 합계**의 자원 총량·오브젝트 개수 상한(admission 검사, 초과 시 403, 소급 없음).
  - ⚠ CPU/메모리 Quota가 걸리면 모든 새 파드는 requests/limits **명시 필수** → LimitRange와 반드시 짝.
  - 당당: 좁은 자원(worker 8Gi/2CPU) 분배 + obsv-ns 메모리 폭주 피해를 ns 안에 격리하는 방화벽.
- **27 LimitRange** — **개별** 컨테이너·Pod·PVC의 기본값(defaultRequest/default)·min/max를 admission 시점에 강제하는 정책.
  - ⚠ admission 시점에만 적용 — 기존 파드 영향 없음, 노드 실제 용량은 안 봄(총량은 Quota, 배치는 스케줄러 몫).
  - 당당: defaultRequest 자동 주입으로 Quota 거부 문제 보완, max로 "워커 한 대 독점" 실수를 입구에서 차단.
- **28 PDB** — 노드 드레인 등 **자발적 중단** 시 동시 다운 가능 파드 수를 제한하는 오브젝트(minAvailable/maxUnavailable 택1).
  - ⚠ **Eviction API에만 작동** — `kubectl delete pod`는 우회, 하드웨어 장애(비자발적)는 못 막음; 축출 여유 0이면 drain 무한 블록.
  - 당당: Alertmanager 3에 `minAvailable: 2`로 gossip 정족수 유지, 축출 여유 1개 이상 확보 원칙.

## 3. 헷갈리는 세트 비교표

**① Role vs ClusterRole**

| 구분 | Role | ClusterRole |
| --- | --- | --- |
| 범위 | 한 네임스페이스 | 전역(namespace 필드 없음) |
| 대상 | ns 내 리소스만 | + non-namespaced(Node·PV·StorageClass) + nonResourceURLs(/metrics) |
| 당당 | 일반 워크로드 기본 | Prometheus·KSM·Kyverno·cert-manager 등 소수, 읽기 전용 좁게 |

**② RoleBinding 4조합**

| 바인딩 | 참조 | 가능? | 효과 |
| --- | --- | --- | --- |
| RoleBinding | Role | ✅ | 그 네임스페이스 권한 |
| RoleBinding | ClusterRole | ✅ | 전역 정의를 그 ns로 **축소**(재사용 패턴) |
| ClusterRoleBinding | ClusterRole | ✅ | 클러스터 전역 부여 |
| ClusterRoleBinding | Role | ❌ | **유일한 불가** — 스코프 모순 |

**③ Deployment vs StatefulSet vs DaemonSet**

| 구분 | Deployment | StatefulSet | DaemonSet |
| --- | --- | --- | --- |
| 파드 성격 | 대체 가능(무상태) | 고유 신원(ordinal 고정) | 노드당 정확히 1 |
| 스토리지 | 기존 PVC 참조(공유) | volumeClaimTemplates로 파드별 전용 | 노드 로컬(hostPath 등) |
| 개수 | replicas | replicas + 순서 보장 | 노드 수 = 파드 수 |
| 당당 | 앱 3계층·Grafana·Gateway | Prometheus·Alertmanager·Vault·DB | node-exporter·OTel Agent |

**④ Secret vs SealedSecret vs etcd 암호화**

| 구분 | 보호 구간 | 원리 | 한계 |
| --- | --- | --- | --- |
| Secret | (보호장치 아님) 주입 통로 | base64 인코딩 | 암호화 아님, 기본 etcd 평문 |
| SealedSecret | Git 이동·저장 | 공개키 봉인, 컨트롤러만 복호화 | 언실 후엔 평범한 Secret |
| etcd 암호화 | etcd 디스크·백업(at-rest) | apiserver가 쓰기 전 암호화 | API 조회는 복호화됨 → RBAC 별도 필요 |

**⑤ PSA vs SecurityContext vs Kyverno**

| 구분 | 역할 | 단위 | 성격 |
| --- | --- | --- | --- |
| PSA | 기준선 검사(gate) | 네임스페이스 라벨 | 내장, 3레벨 고정(세밀 조정 불가) |
| SecurityContext | 검사를 통과할 실제 실행값 | 파드/컨테이너 매니페스트 | 워크로드가 스스로 선언 |
| Kyverno | 세밀 맞춤 정책 + mutate/generate | ClusterPolicy(전역)/Policy(ns) | CRD, PSA 빈틈 보완 |

**⑥ PV vs PVC vs StorageClass**

| 구분 | 정체 | 스코프 | 비유 |
| --- | --- | --- | --- |
| PV | 실제 스토리지 자원 | 클러스터 | 실물 |
| PVC | 사용 요청서(파드가 마운트) | 네임스페이스 | 주문서 |
| StorageClass | 동적 프로비저닝 템플릿 | 클러스터 | 공장 설정 |

**⑦ liveness vs readiness vs startup**

| 구분 | 실패 시 행동 | 목적 | 당당 포인트 |
| --- | --- | --- | --- |
| liveness | 컨테이너 재시작 | 데드락·행 복구 | 자기 생존만(외부 의존성 금지) |
| readiness | Endpoints 제거(트래픽만 차단) | 무중단 배포·과부하 회피 | DB 미연결 시 재시작 대신 트래픽 차단 |
| startup | 성공 전까지 다른 프로브 정지 | 느린 시작 보호 | dang-ai-ns 모델 로딩 수십 초 |

## 4. 우리 프로젝트 결정 카드 (선생님이 물을 8가지)

1. **PSA: restricted 원칙 + 완화 최소(정정 반영)** — 전 ns `enforce=restricted`, `dang-db-ns`만 baseline(root DB 이미지 — runAsNonRoot는 restricted 전용 요구).
   근거: 공식 PSS상 hostPath·hostNetwork는 **baseline도 금지** → node-exporter·OTel Agent는 privileged 필요, DaemonSet만 별도 ns 분리로 privileged 범위 최소화(원 "obsv-ns baseline" 결정은 정정 — 92 통합본 참조).
2. **Vault replica 1 (PoC)** — StatefulSet 구조는 올바로 잡되 replica 1 고정.
   근거: Raft 정족수 3은 물리 3호스트 필요, 우리는 2호스트 — 가짜 HA 대신 PoC 명시, `vault sealed` 조기 알람으로 보완.
3. **Alertmanager 3 (gossip)** — 3-replica HA + PDB `minAvailable: 2`.
   근거: gossip은 정족수 불요라 물리 2호스트에서도 HA 유효(Raft와 대비), 피어 발견은 Headless DNS.
4. **Grafana provisioning + SQLite** — Deployment 무상태 운영, 대시보드·데이터소스는 provisioning 코드로.
   근거: 데이터는 각 수집기(Prometheus·Loki)에 있고 설정은 Git으로 재생성 가능 — 전용 PVC 불필요.
5. **requests/limits 실측 기반** — 도커 실측 관측치 + 노드 용량(8Gi/2CPU) 상한으로 설정, LimitRange max로 강제.
   근거: 임의 수치는 과소(OOMKill)·과대(스케줄 불가) 양쪽 위험 — 실측이 유일한 근거.
6. **CNI는 Calico/Cilium 필수** — NetworkPolicy 지원 CNI를 이관 전제조건으로 못박음.
   근거: 미지원 CNI(flannel 단독)면 default-deny 전 정책이 조용히 무효 — 적용 후 연결 테스트로 실차단 검증.
7. **시크릿 3계층** — SealedSecret(Git 부트스트랩) + Vault(런타임 동적, PoC) + etcd 암호화(최후방어) 직렬.
   근거: 각 층의 보호 구간이 다름(Git/런타임/디스크·백업) — 서로 대체 불가라 겹친다.
8. **부하테스트는 K8s 이관 후로 이월** — HPA 임계값·Quota 수치는 1차 상한만, 확정은 이관 후 실측으로.
   근거: 도커 실측치는 있으나 K8s 환경 특성이 다름 — metrics-server 설치 후 `kubectl top` 실측으로 확정.
